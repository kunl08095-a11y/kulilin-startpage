KULILIN 起始页 Firefox 1.7.0
============================

这个目录是 Firefox / Zen 用的包。仓库根目录的 Chrome / Edge 版本仍是 1.6.6，没有改。
这里的 ZIP 没有签名，也没有提交到 AMO。它不能当作已经发布的正式版长期安装。

一、这次改了什么

Firefox 清单在原来的新标签页之外，增加了主页声明：

  chrome_url_overrides.newtab = index.html
  chrome_settings_overrides.homepage = index.html

Ctrl+T 仍打开同一个起始页。主页也指向同一个 index.html。
附加组件 ID 仍是 startpage@kulilin.com。权限仍只有 storage，没有新增。
页面、搜索和快捷网站代码没有改。已有的 chrome.storage 数据还在这个 ID 下面。

二、Firefox 实际会怎样做

依据 mozilla-central 55b1289e3236（2026-11-19）的源码，不是本扩展自己另写的开关：

- 扩展只能用清单里的 chrome_settings_overrides.homepage 设置主页。
  Firefox 把它解析成这个扩展自己的页面：
  moz-extension://<本配置文件里的 UUID>/index.html。
  相对地址 index.html 只会变成一个主页，不能写成多页。
- 扩展启动时，Firefox 调用 homepage_override 这项设置，写入
  browser.startup.homepage。升级到 1.7.0 时也会走这一步。
- 浏览器默认 browser.startup.page 是 1，也就是启动时打开主页。
  这时第一个窗口会使用上面的主页。
- browser.startup.page 为 3 时，表示「打开上次的窗口和标签页」。
  SessionStartup 会恢复上次的会话。browser-init.js 在
  willOverrideHomepage 为真时不加载主页。扩展没有接口可以改这个启动方式，
  也不能替你关掉会话恢复。
- 启动方式为空白页（值为 0）时，启动也不会打开主页。
- 主页按钮会打开这个主页。启动方式为 1 或 3 时，之后新建的窗口也会打开主页。
  恢复会话只替换启动时的第一个窗口，不会改掉已经写好的主页设置。
  Ctrl+T 走的是新标签页覆盖，和这次的主页声明是两件事。
- Firefox 不是先问过你再写入。主页被打开时，会提示「你的主页已更改」：
  主按钮是保留（Keep Changes），次按钮是管理主页（Manage Homepage）。
  点保留之后，不再为这个扩展反复弹出。点管理主页会打开主页设置。
- 你后来在设置里自己换了主页，Firefox 会把控制权记成用户的选择。
  之后扩展再次启动，不会把主页悄悄改回去。
- 禁用或卸载扩展后，Firefox 会按它保存的设置恢复之前的主页。
- 没有允许这个扩展在隐私窗口运行时，隐私窗口不用扩展主页，而用浏览器默认主页。
  这次没有为隐私窗口增加权限。要在隐私窗口使用，需要在附加组件详情里自己允许。
- 若别的扩展也声明了主页，Firefox 按安装时间决定谁优先。你仍可在设置里改回自己的主页。

三、已经装了 1.6.6 的人

签名版 ID 就是 startpage@kulilin.com。更新后的 1.7.0 使用同一个 ID，
所以快捷网站和搜索设置仍读原来的 storage，不会另起一份。
页面文件也还是原来的 index.html。

更新后请完全退出浏览器再打开。如果更新当时第一个窗口已经用旧主页打开，
这一次可能仍是旧页面；退出重开后，主页设置才会用于下一次启动。
前提仍是启动方式为「打开主页」，而不是恢复上次会话。

四、你需要自己做的

1. 这个 ZIP 未签名。可用 about:debugging → 此 Firefox → 临时加载附加组件 试用。
   临时加载在浏览器完全退出后会消失，不能永久安装。
   若本机已启用签名版，同一个 ID 的临时包可能装不上或互相顶替。
   试用前先禁用签名版，试完退出，再启用签名版即可回到 1.6.6。
   本次没有提交 AMO，也没有签名。
2. 打开 设置 → 主页。想使用起始页时，在提示里选保留。
   若要换回原来的主页，在这里自己改。
3. 启动方式请选「打开主页」。
   若保持「打开上次的窗口和标签页」，启动时仍恢复上次的标签，不会先打开起始页。
4. Ctrl+T 的新标签页和原来一样，不需要重新设置。

五、Zen

Zen 使用同一套 Firefox 扩展接口，所以主页声明同样写在这份清单里。
本次对照了 zen-browser desktop bc376a42（2026-11-20）的
ZenSessionManager.sys.mjs：当 browser.startup.page 不是 3 时，
Zen 仍会恢复置顶标签，并继续做窗口同步。
「从上次停下的地方继续」或恢复上次窗口时，启动仍可能是上次的工作区。
扩展不能关掉 Zen 的会话恢复。

你的 Ctrl+T 已经能打开这个起始页，所以这次没有改新标签页。
如果某个启动窗口只出现 Zen 的空白地址栏，那是 Zen 自己的新标签替换
（about:config 里的 zen.urlbar.replace-newtab）。那不是这个主页声明能强制关掉的。
本次没有在 Firefox 或 Zen 里实际启动浏览器做验证。
